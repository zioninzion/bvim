# Reference implementation review

The table records the revisions inspected for this build. The comparisons describe code paths relevant to an offline reader. No reference project’s source or Bible dataset is included in bvim.

| Project | Reading and navigation | Storage and search | Design lesson and tradeoff |
|---|---|---|---|
| [nehemiaharchives/bbl, df9c98ae](https://github.com/nehemiaharchives/bbl/tree/df9c98ae) | Reference-first CLI, short book names, open-ended verse ranges, language and translation selection with an inline `in` clause. Commands support history and corpus filters. | Kotlin multiplatform core. ZipBibleResourcesReader opens chapter-specific text members and translation index files. SearchEngine caches language analyzers and in-memory Lucene directories, combines field filters and terms, then returns verse pointers. | The same reference can drive reads and comparison. Language-specific analysis has clear research value, with extra binaries, index packaging and deployment work. bvim uses stable references and one local FTS index. |
| [prestonharberts/bib, 60bce40](https://github.com/prestonharberts/bib/tree/60bce40) | Compact shell references, context around a verse, sequential result browsing. The parser normalizes numbered book names, resolves abbreviation aliases through jq and handles single-chapter books. | Bash and chapter Markdown files. bib locates verse headings with awk and applies sed formatting. bibs recursively greps files, recovers a verse number from preceding headings, then invokes bib to render it. | Easy to inspect sources and pipe output. Mapping line hits back to references repeatedly launches tools and depends on the Markdown structure. Store the reference alongside each indexed verse. |
| [wisyhambolu/Bible-Cli, bf293ed](https://github.com/wisyhambolu/Bible-Cli/tree/bf293ed) | Guided menus, bookmarked references with notes and context around hits. Regexes parse references including numbered books. RapidFuzz ranks book names and the interactive flow can confirm a match. | Python loads dataset.json into memory and builds a book-name dictionary. Keyword, regex and advanced searches iterate books, chapters and verses. | Guided discovery and context previews help beginners. Corpus startup cost and repeated scans grow with installed editions. Offer suggestions while typing and keep the reader at its origin until acceptance. |
| [mittel-labs/bibleit, 4d8df73](https://github.com/mittel-labs/bibleit/tree/4d8df73) | Textual synchronizes translation panes. Tab changes pane, Ctrl-F finds text, Ctrl-G opens Strong’s, and colon opens a completable reference prompt. Relative verse and chapter commands use current pane state. | Python uses native libbibleit cursors and translation headers. text_find.py constructs normalized reference/text rows, caches a bounded number of translation indexes and scans those rows for substrings up to a limit. | Strong separation of navigation and views, especially synchronized comparison. Cached scans consume per-edition memory. bvim borrows the shared cursor and uses FTS for term lookup. |
| [thenewmantis/bbl, 6c71b4f](https://github.com/thenewmantis/bbl/tree/6c71b4f) | A single expression combines reference lists, chapter or verse ranges and scoped slash search. `-o` selects a reading. bookmatches accepts cleaned book abbreviations and name prefixes. | Shell and awk over reading-specific TSV. The parser builds scope arrays. Ordinary and rough patterns are evaluated against the reading, including optional book/chapter filters. | A small declarative query can replace several menus. Prefix matching across multiple books and dense punctuation need feedback. bvim uses explicit ambiguity errors and a separate scope option. |

## Original-language candidates

- OSHB is a suitable first Hebrew adapter. Its OSIS word records carry persistent word IDs, segmented lemmas and morphology. Preserve the full segmented identifier. Credit the project for its CC BY 4.0 annotations and record the WLC text provenance separately. [OSHB documentation](https://github.com/openscriptures/morphhb)
- MorphGNT provides Greek surface, normalized form, lemma, POS and parsing code on the same source row. A native adapter can validate the surface against the source edition and preserve position. The project distinguishes rights in its parsing data from the underlying SBLGNT text. [MorphGNT data and attribution](https://github.com/morphgnt/sblgnt)
- MACULA includes multiple base texts, syntactic trees, glosses, senses and TSV exports. Its component provenance makes a single generic license flag insufficient for a distributable pack. Start with an identified release and a specific TSV layer. [MACULA source descriptions](https://github.com/Clear-Bible/macula-greek)
- Open Scriptures Strong’s dictionaries are candidates for headword lookup. A dictionary key can identify a lexical entry, while occurrence and sense claims require separately sourced annotations. [Open Scriptures Strong’s](https://github.com/openscriptures/strongs)

The implemented provider accepts local JSONL entries with source and license metadata. A verse link supports contextual lookup. A word link additionally requires a matching edition, position and literal surface. No aligned lexical pack ships with this release.
